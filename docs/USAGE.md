# 使用手册

> WorkBuddy 网关 · Android 本地 OpenAI 兼容网关
> 应用版本 1.0 · 接口 `http://127.0.0.1:7863/v1`

本手册覆盖：页面说明、视频 / 音频通路细节、诊断排查、权限、开源许可与已知限制。

---

## 〇、v1.1 行为变化

- **会话粘性**：同一段对话固定在同一账号（30 分钟滑动 TTL）。客户端带了 `conversation_id` / `session_id` / `metadata.conversation_id` 就用它，否则按「模型 + 前两条消息」指纹识别。账号被冷却或请求失败会自动解绑。
- **冷却分级**：402 → 次日 04:00（1 小时下限）；429 → 10 分钟起指数退避，1 小时封顶，成功一次即重置；404 → 固定 60s。想改回旧行为，把 `cooldown.soft_rate` 设回 `60s`、`hard_reset_hour` 设成当前小时即可。
- **运行健康**：不持唤醒锁，服务被冻结时界面会显示「已 N 秒没有心跳」，并累计冻结/启动次数。

## 一、功能迭代记录

| 项目 | 说明 |
|---|---|
| **状态栏 / 导航栏沉浸** | 状态栏与导航栏透明，内容延伸到系统栏下；按 insets 给根布局加 padding，横屏时侧边导航栏也不会挡内容；浅色背景配深色图标 |
| **横屏两列布局** | 横屏且宽度 ≥600dp 时，每个页签的卡片自动分到两列（左右交替），减少滚动；竖屏保持单列 |
| **两个版本** | 完整版 170 MB（含音频模型）与轻量版 12 MB（仅转写）。轻量版自动隐藏音频精度 / 分类测试，服务强制 `audio_mode=asr` |
| **开源许可页** | 概览底部「开源与许可」列出 TFLite、YAMNet、PANNs、上游协议项目及各自许可证 |
| **不再持有唤醒锁** | 删掉 `PARTIAL_WAKE_LOCK` 和 `WAKE_LOCK` 权限，只保留前台服务；不再强行阻止 CPU 休眠 |
| **四个页签** | 概览 / 模型 / 账号 / 任务，替代原来一页到底 |
| **模型列表 + 积分倍率** | 显示上下文、最大输出和 `x0.79` 这类倍率；`x0.00` 标「免费」，`—` 表示上游没给。倍率优先取桌面端 `/v3/config`，失败回退内置表 |
| **账号积分** | 每个账号显示剩余 / 总量、已用、百分比进度条，以及可用 / 冷却 / 禁用原因 |
| **签到** | 「账号」页一键签到，逐个账号刷新积分并自动解冻冷却账号 |
| **成长任务** | 「任务」页拉取任务列表，显示进度与奖励；已完成的可单个领取或一键领取，另附任务中心入口 |
| **重置状态** | 清除本地 `disabled / 冷却 / 积分缓存`，不清凭证；重新登录换 token 后也会自动解冻 |
| **错误提示** | 503 从笼统的 `all accounts unavailable` 拆成「没配置账号」和「全部冷却/禁用 + 原因」 |
| **重启噪音** | 重启服务时不再出现 `read interrupted by close()` 的假错误 |
| **转写与声音事件同条输出** | 音频默认（hybrid）就把 ASR 转写和声音事件拼成一段交给模型；视频同样把台词和声音事件放在画面说明后。不是两个独立请求 |
| **转写尽量带时间戳** | 解析 ASR 响应里的 `segments` / `utterances` / `sentences`（兼容秒与毫秒），有就逐行输出 `0:03-0:05 你昨天去哪了`；没有则退化为整段文本 |
| **声音标注重写（家族 SED）** | 从「逐帧 argmax 单标签」改成「15 个声音家族各自做双阈值检测」，允许同时输出说话 + 音乐 + 笑声；副语言（笑/喘/叫/哭）用 top1+0.5×top2 恢复被摊薄的分数 |
| **PANNs 不再覆盖短事件** | 10 秒窗口的整体判断只用于补 YAMNet 没归类的部分，不再把 2 秒的掌声改成「音乐」 |
| **噪声/纯音抑制** | 正弦音、白噪声、静音占主导时压掉其他语义事件，避免测试音被标成「电话铃声」 |
| **家族中文名** | 输出改成「0:12-0:15 说话（女）」「0:20-0:22 撞击声」，不再是原始类名拼接 |
| **修复视频「模型说看不到」的误判** | 抽帧失败时原本会把 `video_url` 原样透传，上游静默过滤并注入「当前模型不支持视频」提示，表现为模型看不到视频、`prompt_tokens` 只有几十。现在失败会替换成明确文字（含失败原因），不再伪装成模型限制 |
| **内置离线测试视频** | 诊断用的示例 URL 已 404（`static-openapi.stepfun.com/.../case1.mp4`），改为 APK 内置 3 秒 360×240 H.264+AAC 视频（97 KB），不依赖外网 |
| **视频诊断分两步** | 先调 `/admin/video-probe` 只跑本地管线（下载 → 抽帧 → 音轨 → 转写），显示字节数、帧数、事件、耗时与失败原因；成功后才发给模型 |
| **用 prompt_tokens 判定责任方** | 模型说看不到时，`<300` 说明图片没进请求（网关侧），`>300` 说明图片已发但被模型/上游过滤 |
| **日志记录管线实况** | 每次视频处理打 `video: parts= frames= bytes= src= events= transcript= elapsed= failed= reason=` |
| **局域网访问** | 概览页一键开关：关闭时只监听 `127.0.0.1`，开启后 `0.0.0.0` 并显示 `http://<手机IP>:7863/v1`；非本机监听强制要求 API Key |
| **国际版账号登录** | 「登录账号」弹出区域选择，国际版走 `www.workbuddy.ai`，UA 与桌面端 5.8.4 一致；凭证按返回的 domain 落盘，重启后自动按区域路由 |
| **内置网页客户端** | 浏览器打开 `http://<IP>:7863/` 就能聊天，支持文字、图片、音频（走转写+音效识别），Key 存浏览器本地；无需装客户端 |
| **修复图片被当成音频（回归）** | v1.9 重写 `audioSource` 时，对所有 part 都执行音频提取，`image_url` 的 url 被误认成音频源 → 解码失败 → 被替换成「音频处理失败」占位。表现就是模型说「没收到图片」。现在只有明确是音频的类型才进入提取 |
| **修复抽帧被同一 bug 吃掉** | 视频抽出的 `data:image/jpeg` 帧也会被误判成音频并被替换，模型只剩音轨标签。这也解释了「发视频只收到音乐标签」 |
| **图片 part 归一化** | 兼容 Responses API 写法：`input_image` / `image` / 字符串形式的 `image_url` 统一转成 `{"type":"image_url","image_url":{"url":...}}`；不转的话上游会直接忽略，表现为模型说「没有收到图片」 |
| **模型能力标注** | `/v1/models` 增加 `supports_images`，App 模型页显示「可看图」，换模型时不用盲试 |
| **视频对白转写** | 解出视频音轨（16kHz 单声道 WAV，最多 5 分钟）调 ASR，把台词写进视频说明；之前只报「有说话声」，不报说了什么 |
| **三层声音输出** | 事件带 `group`（语音/音乐/撞击/自然/车辆/家居）、`gender`、`pitch`；摘要从「标签 时间」改成「时间 描述」 |
| **音乐画像** | 从 PANNs 多标签里抽风格、乐器、人声、情绪，并估算 BPM；不再只说「音乐」 |
| **事件引导抽帧** | 先分析音轨，在有声音事件的时刻附近取帧，剩余预算均匀铺；每帧带时间戳 |
| **抽帧无极调节** | 帧数 4–24 或按声音事件自适应、分辨率 480–1280px、质量 50–95，三根滑杆实时预估体积 |
| **移除原生音频** | 上游已证明不支持 `input_audio`，删掉按钮与分支；旧配置里的 `native` 自动迁移为 `hybrid` |
| **第三方音频兼容** | 修了三处会导致上游 `400 unsupported content type` 的问题：OpenAI 标准的纯 base64 `input_audio.data`、`input_audio` 直接是字符串、`audio_url` 形态；只给 file id 时不再透传 400，改用说明文字占位 |
| **PANNs 精细分类** | 新增 PANNs CNN14（AudioSet 527 类，多标签）：先用 YAMNet 定位事件，再对最多 5 个 10 秒窗口精判，事件标签替换为更可信的类别，并附 `tags` 多标签 |
| **音频精度切换** | 诊断区可选「快速 4MB（YAMNet）」/「精细 160MB（YAMNet + PANNs）」；精细模式首次分析会加载模型 |
| **本地音频分类（YAMNet）** | 内置 YAMNet（AudioSet 521 类，TFLite），音频先按 0.975s 窗口、0.48s 步长逐帧分类，再聚合成「时间段 + 事件」，中文标签 352 条；完全离线、不消耗积分 |
| **音频模式三档** | 「仅转文字」/「转写+音效」（默认）/「原生音频」。hybrid 会把 ASR 转写与音效时间轴一起交给模型 |
| **视频音轨识别** | 抽帧时顺带分析视频音轨，把「视频原声里有什么」写进说明文字，模型不再只知道画面 |
| **音频分类测试** | 诊断区可直接选一个音频文件，在本地跑完整流程并显示事件、top 类别、耗时与原始 JSON |
| **原生音频模式（实测不可用）** | 诊断区可切「ASR 转文字 / 原生音频」；原生模式把音频改写成 `input_audio` 直接交给模型。**实测上游不接受，不要用**，默认保持 ASR |
| **音频自动转写** | 识别 `input_audio`、`providerData.acpResourceLink`（audio/*）、audio file part，下载后调 WorkBuddy ASR `/agenttool/v1/asr`，把音频 part 换成转写文本 |
| **临时文件清理** | 服务启动时清掉上次遗留的 `wbvideo-*` / `wbaudio-*`，临时目录放 `.nomedia`；抽帧只在内存里，不写相册 |
| **API 层视频抽帧** | 收到 `video_url` / `input_video` / `data:video/*` 时，自动落到本地临时文件，由内置抽帧服务取 8 帧（768px JPEG），改写成 `image_url` 后再发给视觉模型；对客户端透明 |
| **上游身份切换** | 诊断区可选 CLI / WorkBuddy 桌面端 / VS Code 插件；切换后按 Hub 抓包的 `X-IDE-*`、`X-Agent-*`、会话 ID 和对应域名发请求，用来验证视频能力是否被产品身份限制 |
| **视频通路测试** | 「概览」页新增按钮：用公网 MP4 + `video_url` 直接打 `step-5-preview`，弹窗显示判定、HTTP 状态码和原始响应，可一键复制 |
| **请求体 24MB + 413** | 原 8MB `LimitReader` 会静默截断，改成 24MB 并在超限时明确返回 `413 payload_too_large`；日志只记录 content part 类型，不记录内容 |
| **修复本机 HTTP 被拦截** | targetSdk 28+ 默认禁止明文 HTTP，v1.1 的模型/积分/任务请求会被系统拦下并报 `Cleartext HTTP traffic to 127.0.0.1 not permitted`；v1.2 显式允许明文（仅用于访问本机 7863，不改变上游 HTTPS） |
| **国际版凭证** | 配置迁移为 `region: auto`，国内 + 国际凭证都会加载，按各自 domain 路由 |

## 二、安装 / 升级

### 新装

1. 把 `WorkBuddyGateway-v1.17.apk`（或 `-lite.apk`）传到手机；
2. 点击安装，允许「未知来源」；
3. 首次打开允许**通知权限**（前台服务需要）。

### 从 v1.0 ~ v1.16 升级

直接用同一个 APK 覆盖安装即可，签名一致，`config.json`、`auths/`、`state.json` 都会保留；启动时会把旧的 `region: cn` 自动迁移成 `auto`。

如果系统提示「签名不一致」，说明装过别的渠道包，只能卸载重装（凭证会丢）。

## 三、页面说明

### 概览

- 运行状态、启动 / 停止；
- Base URL 与 API Key，一键复制；
- 账号总数 / 可用数；
- 网页版地址（可一键打开 / 复制）、局域网开关与手机 IP；
- 诊断区：上游身份（CLI / 桌面端 / VSCode）、音频模式（仅转文字 / 转写+音效）、音频精度（快速 / 精细）、视频抽帧（省流 / 标准 / 高精）、视频通路测试、音频分类测试；
- 最近 16 行日志，「全部」可看完整日志。

### 模型

读取 `/v1/models`，每行：

```
glm-5.2                    x0.79
上下文 131k · 输出 32k
```

- 倍率来源：优先桌面端 `/v3/config` 的 `credits` 字段，缓存 1 小时；拉不到时用内置快照兜底，仍未知显示 `—`；
- 模型清单本身来自账号可用的 CLI 通道，不是全量目录。

### 账号

- 「登录账号 → 完成登录」走手机浏览器 OAuth；
- 「导入凭证」选电脑上的 `workbuddy-*.json`；
- 「刷新积分」查每个账号的剩余 / 总量；
- 「一键签到」逐个签到并刷新积分；
- 「重置状态」清掉本地冷却/禁用标记；
- 每个账号卡片显示：昵称/UID、剩余/总量、进度条、可用状态与原因。

### 任务

- 显示能量、连续签到天数；
- 任务列表：名称、描述、进度、奖励、接取状态；
- 进度达标的任务右侧出现「领取」，「一键领取」批量领；
- 「打开任务中心」跳官方网页。

> 说明：需要真实使用行为的任务（对话、使用专家/团队等）无法在这里伪造完成，只做「读取 + 领取已完成」，不伪造上报事件。

## 四、视频通路测试

「概览 → 诊断 → 视频通路测试」现在分两步，用的是一段 **APK 内置的 3 秒视频**（360×240，H.264 + AAC，97 KB），不需要联网。

**第一步 · 本地管线**（调 `/admin/video-probe`，不发上游、不消耗积分）

弹窗会给出：

```
本地管线：成功
  来源 data · 视频 96.8 KB · 帧数 8 · 声音事件 2 · 台词 0 字 · 耗时 1840 ms
  声音：0:00-0:02 正弦音
```

失败时直接给原因，例如：

```
本地管线：失败
  来源 url · 视频 0 B · 帧数 0 · 声音事件 0 · 台词 0 字 · 耗时 381 ms
  原因：下载视频失败：HTTP 404（链接可能已过期或需要授权）
```

这种情况下**不会再发给模型**，因为发过去也只会得到「我不支持视频」，反而误导。

**第二步 · 模型**（本地成功后才执行）

结论会结合 `prompt_tokens` 判定责任方：

| 结果 | 含义 |
|---|---|
| 成功，模型描述了画面 | 整条链路通 |
| 模型说看不到，`prompt_tokens < 300` | 图片没进请求，问题在网关（看本地管线的帧数） |
| 模型说看不到，`prompt_tokens > 300` | 图片已发出，是模型/上游过滤了图像 |
| HTTP 400 / 413 / 503 | 请求被拒、体积超限、账号不可用 |

**常见失败原因**

| 本地管线报错 | 原因 |
|---|---|
| `下载视频失败：HTTP 404/403` | 链接过期、需要签名、防盗链 |
| `创建临时文件失败（TMPDIR 不可写）` | 应用私有目录异常，重启 App 或清除数据 |
| `本地抽帧服务连不上` | 抽帧服务没起来（通常是 App 被系统冻结） |
| `no frame decoded (unsupported codec...)` | 编码系统不支持（HEVC 10bit、AV1） |
| `no decodable audio` | 无音轨或音频编码不支持；画面仍应抽到帧 |

## 五、音频与视频输入

### 音频（转写 + 本地音效识别）

v1.6 起识别这些音频 part：

- `{"type":"input_audio","input_audio":{"data":"base64...","format":"ogg"}}`
- `{"type":"input_audio","input_audio":{"data":"<纯 base64>","format":"wav"}}`（OpenAI 标准，v1.9）
- `{"type":"audio_url","audio_url":{"url":"https://...ogg"}}`（v1.9）
- `{"type":"input_audio","input_audio":{"url":"https://...ogg"}}`
- `{"type":"file","file":{"file_data":"data:audio/...","filename":"a.ogg"}}`
- ACP 附件：`type:"input_text"` + `providerData.acpResourceLink`（`codebuddy_mimeType` 为 `audio/*`）

处理分两段，默认都开（`audio_mode: "hybrid"`）：

```
音频 part
   ├─ WorkBuddy ASR（/agenttool/v1/asr）→ 转写文本
   └─ 本地 YAMNet（127.0.0.1:7864/audio）→ 事件时间轴
        ↓
拼成一段 text：转写内容 + 「0:00-0:12 语音；0:12-0:15 掌声」
```

发给模型的样子：

```
音频《meeting.ogg》的转写内容：
今天先过一下 Q3 的数据……

音频《meeting.ogg》里的声音事件（本地 YAMNet 分类，按时间轴，仅供参考，不是转写）：语音 0:00-2:41；笑声 0:34-0:36；掌声 2:41-2:44
```

**YAMNet 是什么**：Google 的 AudioSet 分类模型，521 个类别，覆盖人声、动物、乐器、音乐流派、交通工具、家居器物、自然声、撞击与爆裂等。输入 16kHz 单声道，0.975 秒一帧，0.48 秒步长；一段 3 分钟音频约 375 帧、耗时 2–5 秒（中端机）。

后处理做了三件事，避免结果碎片化：

1. 跳过 `Silence`、`Inside/Outside`、`Reverberation`、`Echo` 这些「声学环境」类，不当作事件；
2. 单帧抖动平滑（A B A → A A A），并把相邻事件裁到不重叠；
3. 短于 0.45 秒且置信度低于 0.45 的碎片丢弃，最多保留 10 段。

**两档精度**（同样在诊断区切换）：

| 精度 | 模型 | 体积 | 能力 | 耗时（3 分钟音频） |
|---|---|---|---|---|
| 快速 | YAMNet | 4 MB | 521 类，单标签/帧，时间轴 | 约 1–2 秒 |
| **精细**（默认） | YAMNet + PANNs CNN14 | 155 MB | 527 类，多标签；YAMNet 定位 + PANNs 精判 | 5–20 秒 |

精细模式的做法：

```
YAMNet 全量扫描 → 事件时间轴（0:00-2:41 语音 …）
        ↓ 取每个事件中点
PANNs CNN14：最多 5 个 10 秒窗口，527 类 sigmoid（可同时输出 语音 0.91 + 音乐 0.72）
        ↓
事件标签用 PANNs 的 top1 覆盖（置信度 ≥0.25），并附 tags 多标签
```

与 YAMNet 的差别不只是“更准”（AudioSet mAP 0.31 → 0.43），而是**多标签**：一段“有人说话 + 背景音乐 + 远处警笛”的音频，YAMNet 每帧只能选一个，PANNs 能同时给出三个标签。日志会打 `panns windows=N`。

PANNs 的 log-mel 前端在 Java 侧计算（reflect pad、periodic Hann、1024 点 FFT、64 mel、10log10），已与参考实现对齐到 `corr=1.0`；CNN 部分走 TFLite（fp16 权重，4 线程）。

### 转写与事件如何一起给模型

音频（默认 `hybrid`）最终是**一个 text part**，不是两条消息：

```
音频《meeting.ogg》的转写内容：
0:03-0:05 今天先过一下 Q3 的数据
0:06-0:09 第一个是收入

音频《meeting.ogg》里的声音事件（本地 YAMNet 分类，按时间轴，仅供参考，不是转写）：
背景音乐 0:00-2:41；笑声 0:34-0:36；掌声 2:41-2:44
```

视频则是在帧列表后面依次给声音事件和台词，模型一次看到全部材料。

**时间戳取决于上游**：如果 ASR 返回 `segments`（或 `utterances` / `sentences`，字段名 `start/end` 或 `startTime/endTime`，秒或毫秒都兼容），转写会逐行带时间，能和声音事件按同一时间轴对齐；如果没有，只给整段文本，模型仍能结合事件大致判断，但不能精确到“第几秒说了什么”。

### 声音标注 v1.15（家族 SED）

旧实现的三个问题，正好对应你听到的「怪」：

| 旧行为 | 后果 |
|---|---|
| 每帧 argmax 只留一个类 | 说话 + 背景音乐时只能报一个 |
| 父类分数天然最高（Music 0.7） | 永远是「音乐」，风格/人声/乐器全丢 |
| 10 秒 PANNs 窗口覆盖 2 秒事件 | 掌声被标成音乐，时间还对不上 |
| 副语言分数被拆到多个子类 | `Giggle 0.05 + Laughter 0.04` 都过不了阈值，笑声报不出来 |

现在的做法：

1. **15 个家族**：说话 / 唱歌 / 笑声 / 哭泣 / 叫喊 / 掌声欢呼 / 喘息 / 撞击 / 音乐 / 乐器 / 车辆 / 警报 / 自然 / 脚步 / 家居 / 动物。每个 AudioSet 类按「最长关键字」归族（`Drum and bass` → 音乐，`Musical instrument` → 乐器）。
2. **家族分数 = top1 + 0.5×top2**（仅小家族）：笑声族的 6 个类不会再互相摊薄，也不会像全量求和那样把几十个 0.02 加成 0.3。
3. **双阈值滞回**：`on` 起段、`off` 续段、允许 2 帧空洞，减少碎片；不同家族可以重叠（说话 + 音乐 + 笑声同时存在）。
4. **背景声合并**：音乐/车辆/自然只留最长一段，避免一首歌被切成十几行。
5. **噪声抑制**：噪声族（正弦音、白噪声、静音、环境噪声）≥0.70 的帧，压掉其他族。

覆盖率：YAMNet 521 类里 494 类有归属（95%），剩下的是心跳、咬、刮擦这类冷门。

**模型层面也查了**，但没有可直接用的更好选择：

| 模型 | mAP | 体积 | 结论 |
|---|---|---|---|
| YAMNet | 0.31 | 4 MB | 已用，帧级速度快 |
| PANNs CNN14 | 0.43 | 155 MB | 已用，仅整体标签（LiteRT 版只有 clipwise 输出） |
| **CED-Small** | **0.496** | 22 MB | 最好，但 ONNX 内含 STFT，onnx2tf 直接报 `node_STFT` 不支持 |
| EfficientAT mn10 | 0.471 | 24 MB | 同样卡在 mel/STFT 前端 |

CED 要用得先把它 ONNX 里的 STFT 节点剪掉、在 Java 里自己算 64 维 mel，再做 ViT 推理——工程量与风险都不小，暂时没动。当前这版是「不换模型、把已有模型的输出用对」。

**两种模式**（「概览 → 诊断」切换，切换会重启服务）：

| 模式 | 行为 | 适用 |
|---|---|---|
| 仅转文字 | 只调 ASR | 纯语音消息，最省时 |
| **转写+音效**（默认） | ASR + 音频识别（按精度档用 YAMNet 或 PANNs） | 会议、Vlog、带环境音的视频 |


> 精度和模式是两回事：模式决定「音频要不要转文字」，精度决定「音效识别用哪个模型」。默认 `hybrid + fine`。原生音频模式已删除——上游会过滤 `input_audio`，留着只会误事。

> **原生音频实测结论（2026-10）**：上游对 `input_audio` 的处理与 `video_url` 一致——不报错，但内容被过滤，模型只会回复“无法处理音频”。WorkBuddy 的 `/v2/chat/completions` 只处理文本与图片 content part，音频入口只有 ASR。

**事件分组与人物属性**：每个事件除了标签和时间，还带：

- `group`：`speech` / `music` / `impact` / `nature` / `vehicle` / `household` / `other`
- `gender`：`male` / `female`，只对正常说话、唱歌生效
- `pitch`：`low` / `mid` / `high`，由基频估计

基频用自相关算（60–500 Hz），不额外加载模型。**尖叫、叫喊不标性别**——男女的尖叫基频重叠在 300–1000 Hz，硬标就是编。摘要里会写成 `0:43-0:44 尖叫（高音）`，而不是「尖叫（女）」。

**音乐画像**：`music` 字段包含

| 字段 | 内容 |
|---|---|
| `genres` | 风格 top3，如 流行 0.52 / 电子 0.22 |
| `instruments` | 乐器 top3，如 钢琴 / 鼓 / 合成器 |
| `vocals` | 人声类型，如 女声演唱 |
| `moods` | 情绪，如 欢快 / 忧伤 |
| `bpm` | 节拍估计，只在有明显鼓点时输出 |
| `instrumental` | 有人声类全部低分时为 true |

**音频分类测试**：诊断区点「音频分类测试（选文件）」，选手机里任意音频/视频，会显示：

```
0:00  语音  0.91
0:12  掌声  0.71
0:15  音乐  0.66

最可能的类别：
  语音  0.91
  掌声  0.71

模型：yamnet+panns · 总耗时 8420 ms（解码 210 / YAMNet 1180 / PANNs 6900） · 187 帧
```

不经过网关、不消耗积分，用来确认模型在你的设备上工作正常。

**第三方客户端兼容**（v1.9）：

之前有些客户端发音频会收到上游的 `400 unsupported content type at index 0: input_audio`，原因是音频 part 没被识别，原样透传给了 WorkBuddy。现在支持：

| 客户端写法 | 处理 |
|---|---|
| `{"type":"input_audio","input_audio":{"data":"<纯 base64>","format":"wav"}}` | 补 `data:` 前缀后转写 |
| `{"type":"input_audio","input_audio":"data:audio/...;base64,..."}` | 直接解码 |
| `{"type":"audio_url","audio_url":{"url":"https://..."}}` | 下载后转写 |
| `{"type":"input_audio","input_audio":"b9a45a66-..."}`（file id） | 读不到内容，替换成说明文字，**不再让整个请求 400** |

最后一种情况下模型会看到「客户端只提供了文件引用，网关读不到音频本体」，而不是报错。日志里对应 `audio: unreadable audio part type=input_audio`。要真正理解音频，客户端必须上传音频本体（base64 或可访问 URL）——只给 id 的话，网关没有那个文件服务的凭证。

### 视频（自动抽帧）

v1.5 起，代理层会识别这些视频 part：

- `{"type":"video_url","video_url":{"url":"https://...mp4"}}`
- `{"type":"video_url","video_url":{"url":"data:video/mp4;base64,..."}}`
- `{"type":"input_video","input_video":{"data":"...","mime_type":"video/mp4"}}`
- 被客户端误塞进 `image_url` 的 `data:video/*`

处理流程：

```
视频 URL / base64
   ↓ 下载到 gateway/tmp
Android 本地服务（127.0.0.1:7864）
   ├─ MediaCodec + YAMNet：解音轨，出事件时间轴（先做，用来决定取帧位置）
   ├─ MediaMetadataRetriever：按「事件点 + 均匀点」抽帧，带时间戳
   └─ 音轨转 16kHz WAV → WorkBuddy ASR 转写台词
   ↓
改写 messages[].content：
   [0:12] 第 1 帧 …（时间表）
   视频原声里的事件：0:12-0:15 掌声（男）、0:20-0:22 关门声
   视频台词（自动转写，可能有误）：……
   8~16 个 image_url
   ↓
上游视觉模型
```

注意：

- **必须选视觉模型**：`step-5-preview`、`glm-5v-turbo` 等；纯文本模型会忽略图片。
- 抽帧数量由档位决定：省流 6 帧、标准按时长自适应 4–20 帧、高精 16 帧。声音固定用快速模式（YAMNet），避免精判拖慢视频处理。
- 请求体上限 24MB；更大的视频请传公网 URL（下载上限 96MB），不要内联 base64。
- 第一次请求会多花几秒到几十秒：抽帧 + 音轨分析 + 台词转写（ASR 是最慢的一步）。结果不缓存。
- 视频编码要系统支持（H.264 基本没问题，部分 HEVC/AV1 可能抽不出帧）。
- YAMNet 只给「是什么声音」，不给自然语言描述；它不会说“气氛紧张”，只会说“警笛 0:03-0:09”。
- 日志会出现 `video: rewrote N video part(s) as frames`、`audio: prepared N part(s) mode=hybrid` 和 `parts=map[image_url:12 text:2]`（数字随档位变化）。

### 开启局域网

概览页「局域网访问」→ 开启 / 关闭。开启后：

## 七、图片没收到怎么排查

先看日志里这条请求的 `parts=map[...]`：

| 日志 | 含义 | 处理 |
|---|---|---|
| `parts=map[image_url:1 text:1]` + `image: normalized 1 part(s)` | 图片已归一化并发出 | 问题在模型，见下 |
| `parts=map[text:1]` | 请求到网关时就没有图片 | 客户端没发，检查它的图片设置 |
| `parts=map[image_url:1 text:1]`，但模型仍说没收到 | 图片发出去了，模型不吃 | 换支持视觉的模型 |

**换模型**：模型页里带「可看图」的才声明了 `supportsImages`。已知可用的有 `step-5-preview`、`glm-5v-turbo`；纯文本模型会忽略图片，回复“没有收到”。

**如果是 v1.9–v1.11 的版本**：那几版有个回归——`image_url` 会被误认成音频源，解码失败后替换成「音频处理失败」文字，图片其实在进入上游前就被吞掉了。日志特征是 `audio: prepared 1 part(s)` 且 `parts=map[text:N]` 里没有 `image_url`。v1.12 已修复，装新版即可。

**格式兼容**（v1.11+）：有些客户端用 Responses API 的写法：

```json
{"type":"input_image","image_url":"https://..."}     // 字符串
{"type":"image","image_url":{"url":"https://..."}}
```

WorkBuddy 只认 `{"type":"image_url","image_url":{"url":"..."}}`，其他形式会被静默忽略。v1.11 起网关会自动转换，日志里能看到 `image: normalized N part(s)`。

## 十、已知限制

- **APK 未真机实测**：编译、签名（v2+v3）、zipalign、清单 / ABI / dex / assets 都已校验，但当前环境没有 Android 设备；YAMNet 推理本身已在沙箱用同一模型与 TFLite 运行库验证（静音 → Silence 0.80、白噪声 → Static 0.41、440Hz → Sine wave 1.00），Android 侧的解码与抽帧仍需你实测。
- **无唤醒锁的代价**：深度 Doze 下 CPU 可能休眠，后台请求会延迟到系统放行；前台交互时不受影响。需要 7×24 稳定转发的话，建议插电并把本应用加入电池优化白名单。
- **任务接口是逆向端点**：`/v2/activity/growth/tasks`、`/activity/growth/tasks/{code}/claim` 随上游改版可能失效；失效时任务页会直接显示错误。
- **倍率可能不全**：`/v3/config` 需要桌面 UA，部分账号/网络下会失败，此时只有内置快照里的模型有倍率。
- **相册里出现图片**：抽帧只存在内存里，不写文件；临时视频会立即删除，服务启动还会清理遗留文件。相册里的图多半是客户端自己保存的，网关无法代为删除。
- **音效识别精度**：YAMNet 是轻量模型（mAP 约 0.31），安静环境、低音量、强背景音乐下容易漏检或混淆相似类别（如鼓与掌声）。它是“提示模型注意什么”，不是权威标注。
- **不做音乐信息检索**：不给 BPM、调性、和弦、歌手；只给流派级别的粗分类。
- **音频长度**：单次最多分析 180 秒（默认 90 秒），超长音频只取前段；需要全曲分析请分段。
- **精细模式的开销**：模型 155 MB 常驻内存（mmap），首次分析要 1–3 秒加载；每个 10 秒窗口 1–4 秒（取决于 CPU）。低端机或内存紧张时建议切回快速模式。
- **PANNs 只精判最多 5 个窗口**：3 分钟音频只覆盖被 YAMNet 判定为事件的前 5 段，不是全量逐窗推理。
- **性别判断的边界**：正常说话、唱歌准确率较高；笑声次之；喘息、尖叫、叫喊只能给音高，不给性别。
- **BPM 不是万能的**：只在有明显鼓点/节拍时可靠，纯人声、氛围音乐、自由节奏会给出错误值，所以拿不到可信峰值时不输出。
- **视频台词只转写前 5 分钟**：更长的视频只取前段；台词没有逐句时间戳，整段给模型。
- **事件引导抽帧依赖音轨**：完全静音的视频会退化为均匀采样。
- **自签名**：不是应用商店包，系统会提示「未经安全检测」。
- **合规**：多账号、自动签到、对外提供接口都可能违反服务条款；只建议在自己的设备、自己的账号上做技术验证。
